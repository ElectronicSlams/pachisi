# Game adaptation guide

Pachisi carries the existing eSlams visuals forward. It provides **50 explicit game icons and 50 bundled public synthetic demonstration traces**. That is a statement about artwork coverage. It is not a claim that all 50 real Arena/Battlefield renderers, private-hand controls, native renderers or image exporters have moved into this package.

This guide is grounded in the extracted web source at Platform commit `0fa7dfe227fe545036694c915a6b727eb4ee844a`, the October 5 shared-pack decisions, and the subsequent corrected game-visual extraction. The machine-readable [coverage inventory](game-coverage.json) records exact versions, variants, state fields and counts for every game. Examples below use only authored or bundled public synthetic data.

## Decisions retained from October 5

One maintained set of game identities, assets and geometry may have several compositions. A dense match-card loop, Arena setup, game-detail feature and Grand Slams spotlight should not become four competing game implementations. Arena keeps its existing grid, participant seats, game controller and legal inputs. The host keeps authentication, permissions, networking, replay selection, authoritative clocks, outcomes and private-state projection.

The original Arena preview work contained invalid moves, dimensions and disconnected physics. The current bundled traces replace those scenes with Core-generated synthetic states. Do not reintroduce historical examples from old design files. Later current Stadium founder decisions supersede older product rules: model/provider pages and separate Arena/Battlefield Records exist, but the hosted evaluation product remains retired. Product navigation and dates belong to the app; Pachisi does not decide them.

## Version boundary: artwork and current gameplay differ

The bundled artwork is pinned to Core `7731e2f3d712e5f4714d640df670fc0224feede1` with public artwork seed `112`: **50 games, 672 legal transitions, 722 frames**. These are finite reproducible example traces, some ending mid-game. The extraction pass independently reran the Python generator against a clean checkout at that artwork pin: all 50 traces and 672 legal transitions regenerated byte-for-byte. Browser checks also covered all 722 frames for finite geometry. This does not authenticate live matches or certify current tournament rules.

Current Platform contracts instead identify Core **0.6.2**, commit `a935245c96555c5c50a5fd8d48b778a50ad8290e`. The per-game `platformArenaVersion` may differ from the trace's `artworkArenaVersion`. Match both the game **variant** and supported **arena version** before adapting a real replay. Never relabel the artwork pin as the production runner pin. When Core changes, rerun and review the artwork generator against the intentionally selected new pin; do not edit generated frames until they “look right.”

## Choose the right entry point

| Need | Entry point | Ownership and limits |
| --- | --- | --- |
| A static game identity | `GameGlyph` from `@electronicslams/pachisi/game/icons` | Explicit vector artwork for 50 slugs; unknown games get a generic fallback. Parent controls accessible name, selected state and destination. |
| A decorative setup/card/game-page loop | `GameAnimation` from `@electronicslams/pachisi/game/demo` | Bundled synthetic public trace; component owns the preview scheduler. It never fetches or reproduces the adjacent match. |
| A selected synthetic frame without a clock | `LegalDemonstration` from `@electronicslams/pachisi/game/scene` | Stateless rendering of the bundled `DemonstrationFrame` shape. Its state is untyped beyond a generic record and it contains artwork fallbacks/assumptions. It is not a validated universal live-state API. |
| A real, already-adapted simple board snapshot | `Board` from `@electronicslams/pachisi/game/board` and `BoardFrame` from `/game/board-types` | Pure supplied-frame view. Host validates dimensions/tokens/public perspective and owns progression, clocks, actions, result and replay controls. |
| Actual specialized card/control/graph gameplay | Existing Platform viewer, then a deliberately implemented adapter | Do not replace it with a decorative scene or infer that SVG rendering equals live-state compatibility. The per-game table describes what is missing. |
| An exact match/turn social image | Existing authorized host snapshot path | No complete all-family server/headless snapshot adapter is currently exported. A rendered demo is never evidence for a real match. |

### Decorative demonstration

```tsx
import { GameAnimation } from '@electronicslams/pachisi/game/demo';
import '@electronicslams/pachisi/styles.css';

export function SetupArtwork() {
  return <GameAnimation game="go" gameName="Go" presentation="arena"
    group="setup" typography={{ labels: 'var(--font-mono)' }} />;
}
```

The implemented presentation values are `card`, `arena`, `arena-table`, `feature`, `event`; `size` is `full` or `mini`. `arena-table` crops the scene to its public center and suppresses duplicate demo seats/table because the host supplies them. These are compositions of the same trace, not five different legal sequences. October 5's broader `tile`, `stage` and `share` modes describe use cases; they are not additional `GameAnimation.presentation` values. Use icons for tiles, `Board`/existing actual viewers for real stages, and host snapshot services for shares.

```tsx
import { LegalDemonstration } from '@electronicslams/pachisi/game/scene';
import { demonstrationFor } from '@electronicslams/pachisi/game/demos';

const trace = demonstrationFor('pentago');
// Chosen synthetic frame: not a live match, no internal clock.
const frame = trace?.frames[3];
const artwork = frame
  ? <LegalDemonstration game="pentago" frame={frame} />
  : <p>Preview unavailable</p>;
```

Check that the slug exists. Do not pass arbitrary real state into `LegalDemonstration`: it assumes complete known shapes, some hardcoded geometry and bundled caption conventions. A missing property can otherwise produce a misleading fallback or an exception. The source is useful geometry for a future typed adapter after explicit validation and privacy review.

### Real supplied-frame board

```tsx
import { Board } from '@electronicslams/pachisi/game/board';
import type { CellBoardFrame } from '@electronicslams/pachisi/game/board-types';

// Authored example only. In the app, derive this from an authorized public
// replay/session event; normalize and validate it before reaching the renderer.
const frame: CellBoardFrame = {
  kind: 'cells', family: 'grid_3x3', rows: 3, cols: 3,
  cells: ['O', '.', '.', '.', 'X', '.', '.', '.', '.'], last: [4],
};
const view = <Board frame={frame} label="Recorded turn 2: X in the centre, O top left" />;
```

`Board` does not enforce `cells.length === rows * cols`, sanitize a game protocol or determine whether the board is legal. The typed host adapter must do that. Normalize empties to `.`; the declared type's historical allowance for `""` should not be relied on because several render branches treat any non-dot token as occupied. Validate `last`/`line` indexes and finite positive dimensions; reject unsupported variants to a truthful placeholder. Never silently fall back to another game's example.

## Frame structures

| Type | Fields | Interpretation |
| --- | --- | --- |
| `CellBoardFrame` | `kind:'cells'`, `family`, `rows`, `cols`, row-major `cells`, optional `chess`, `last`, `line` | `family` is `grid_3x3`, `connect_four`, `square_board`, `go_board`, or `hex_board`. Geometry is supplied, not inferred from game name. |
| `CardBoardFrame` | `kind:'cards'`, `top`, `bottom`, `played:{top,bottom}`, `centre:{rank,caption}\|null`, optional `winner` | Generic two-seat layout. Null hand entries are backs, played null means unrevealed/absent; no private card inference. This is not a four-seat poker/trick adapter. |
| `PlaceholderBoardFrame` | `kind:'placeholder'`, `family`, `label` | Honest unsupported/missing-state picture. It does not simulate a live game. |

## Motion, responsive layout, themes and accessibility

The common contract below applies to every game; each game entry adds the important exceptions.

- `GameAnimation` advances bundled frames using each trace's `delay` (100 ms for selected control examples, otherwise 900 ms), holds its final frame for 2 seconds and loops explicitly to the opening. That loop reset is not represented as a legal action. Only engine-terminal frames say Complete.
- One visible preview per named group owns the clock. Hover, focus, offscreen and hidden-tab states pause it; reduced motion shows the last frame. A group name scopes competing previews, so use separate groups only when simultaneous playback is intentional and measured.
- `Board` has no state progression or timer. `last` triggers the existing 220 ms arrive cue, Connect Four uses 320 ms drop, and Hex fill uses the move token. Multi-step captures, Pentago rotation, full-card reveal phases and control trajectories require explicit typed transitions; generic frame changes do not promise all those animations. Pause the host clock without inventing wall-clock motion.
- The standard preview uses a responsive 4:3 canvas, CSS container sizing and game-specific SVG/DOM geometry. The non-cell SVG view box is 320 × 240, or 320 × 158 for `arena-table`. `arena` caps width at 360 px; default feature at 380 px; event at 560 px. Respect view-box proportions. Miniatures are decorative summaries, not a substitute for a readable full board. Provide an enlarged view when numbers, marks or CJK labels become too small.
- Use `styles.css` and the existing light/dark tokens. The package does not add the retired six-theme product or recolor the approved brand. Optional label/piece font roles do not guarantee all glyphs exist. Icons are vector; chess uses symbol-font glyphs, Shogi/Xiangqi use CJK text, and card suits/labels are text. Font-independent pieces remain future work; verify legibility before changing fonts.
- `GameAnimation` is announced as “{gameName} game animation”; internal scenes are decorative. `LegalDemonstration` SVG is aria-hidden, so a standalone manually controlled scene needs a labelled surrounding region or an adjacent text equivalent. `Board` is decorative unless `label` is supplied. None of these creates an accessible legal-action grid automatically.
- For an interactive actual game, the host supplies keyboard/focus order, row/column or named-node labels, current turn/result, legal action buttons and announcements. An SVG click region alone is insufficient. Do not identify ownership, valid moves, terminal state or winning path by color alone. Include meaningful status text in both themes.

## Family adaptation recipes

### Cell boards and intersection boards

Write a pure `publicStateToFrame(state, variant)` adapter per game. Check dimensions against the pinned variant, normalize token identity, add authoritative last/line overlays, and return a discriminated unavailable result for malformed or unsupported inputs. Keep legality and legal-target lists in Core/the host. Add fixtures for opening, middle, terminal, capture, pass, missing field, invalid dimensions and each supported seat orientation. Compare the same frame rendered at tile, card, full and zoom sizes in light/dark and reduced motion. For Go/Hex, supply textual goal/coordinate descriptions and preserve intersections/hex skew.

### Bespoke pieces, pits, graphs and private grids

Treat each scene as separate geometry, not a rectangular-board shortcut. Shogi needs drops/promotion/hands; Xiangqi needs intersection coordinates, palaces and river; Morris needs the 24-node graph; Mancala needs pits/stores and side indexing; Backgammon needs points/bar/bearing-off; Battleship needs two distinct public/owner projections. Extract typed geometry from the decorative branch only after auditing every field. Test that state changes preserve identity/counts and cannot disclose concealed fleets or hands. Do not use the preview's convenient fallback values in a real-state renderer.

### Card, tile and trick games

Use a typed public table model with explicit seat IDs, seat ordering, current actor, visible/hidden cards, public counts, phase, pot/trick/score fields and an authorized perspective. A null card means concealed/absent according to the contract, never “fill with a random card.” Keep multi-seat geometry, folds, hand counts and active-seat order distinct from the generic two-row `CardBoardFrame`. Commitments and private hands must not reach public DOM, labels, serialized props or snapshot services. Test unresolved reveal, resolved reveal, folded/empty seat, zero cards, owner/public view, restart and terminal outcomes. Respect the compact variants instead of assuming full traditional rules.

### Sealed actions, bids and offers

The host sends pending/resolved states as a discriminated union. Pending panels contain no private action/bid value; resolved panels contain only publicly revealed values plus actual outcomes. Offer terms are public only when the game contract says so. Do not animate a one-sided reveal before joint resolution, derive a winner from typography, or interpolate through offers the engine never accepted. Test the serialized pending output for absence of hidden values, including accessible labels.

### Navigation grids and control/arcade scenes

Build typed coordinate/unit adapters: row/column for navigation, normalized court for Paddle Ball, radians for CartPole/Lander, explicit abstract progress/lane/distance for Racing/Walker. Reject nonfinite coordinates. Zero is valid. Empty bullets/aliens/puck data means absence or a truthful unavailable state; it never authorizes invented moving entities. The host controls replay time and interpolation only between genuine recorded states. Mark stylized limb geometry as an illustration of the compact engine, not full physical reconstruction. Test paused/final/empty states, boundaries, collisions and scale changes. Native/Skia and headless/export parity require separate adapters and validation.

## Add a game, variant or presentation

1. Record canonical slug, variant, arena version, Core commit, topology, public/owner projection, unit conventions and result contract. A display name is not a game protocol.
2. Add a recognizable vector identity in `src/game/icons.tsx` and its slug to `icon-catalogue.ts`. Unknown fallback coverage does not count as implemented artwork.
3. Extend the generator's explicit public-field allowlist and deterministic plan for a demonstration. Use an intentional clean artwork Core pin; run `scripts/generate-demonstrations.py --core-root /path/to/core --check` with that Core environment. Review regenerated output and counts, legal actions, terminal/excerpt labels and invariants. A fresh Core pin may require API/variant adaptation before this works.
4. Add a specialized scene branch or a typed actual-state adapter. For real games, use validated discriminated inputs and no permissive fallback entity creation. Record missing features as partial/deferred instead of silently using another game or generic cards.
5. Add the entry to `catalogue.ts` and this coverage inventory. Keep the artwork pin separate from host runtime pins. If artwork changes game version, document whether consumers need a compatibility gate.
6. Reuse `card`/`arena`/`arena-table`/`feature`/`event` compositions where suitable. New presentation values require an API and CSS change plus examples; they must not alter game rules, state, hidden-information policy or legal action semantics.
7. Verify every frame for finite geometry and clipping, both themes, small/full/zoom sizes, keyboard/status semantics, paused/hidden/offscreen lifecycle, reduced motion, empty/unknown/malformed input, privacy and deterministic output. Test the packed package in a clean consumer, not only local source aliases.
8. For native or image/video exports, implement and validate a separate thin adapter. Share identity/geometry/transitions where possible, retain platform-appropriate accessibility/hit targets, and compare identical eligible frames. Do not claim support merely because the web demo renders.

## Remaining work and explicit exclusions

Pachisi's initial extraction does not replace actual Arena controllers, selected specialized Battlefield/Pixi viewers, player-owned private-card overlays, per-game rule engines, session networking, permissions, gameplay keyboards, host share services, video pipelines or current product routing. A complete typed actual-state renderer across all families, per-game lazy trace modules, multiple alternate legal traces, font-independent piece artwork, native/Skia adapters and faithful all-family static image exports remain separate work with explicit acceptance checks.

The package currently bundles all demonstration JSON through `demos.ts`; importing it may include all 50 traces. Do not import the demo entry into a simple icon-only header or server-only primitive bundle. Measure application route cost after consumption. Shared source does not prove the Home performance budget, native frame rate or authenticated game completion.
