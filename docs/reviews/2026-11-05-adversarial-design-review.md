| Three deeper recordings | Pinned Core recordings cover a complete Pentago match with both rotation directions, all five Goofspiel rounds, and a Racing lap with left/right steering and braking. All three are rendered by the packed consumer check. |

The package and browser gates record their latest result in [local CI evidence](../validation/local-ci.json). Broader native support, additional live-family adapters and richer independently authored compositions remain future library development. The existing Taxi source-data defect and Bridge dummy-data limitation remain documented in [physics validation](../physics.md).

Pachisi’s strongest asset is the ability to compare the same position across designs, games and placements. Its largest weakness is that a design can earn a place in the catalogue even when it displays the wrong position, loses information a player needs, or falls back to another design. I would fix those failures before expanding the catalogue.

## What the breadth figures establish

- The catalogue registers **170 selectable game/design pairs**. For 46 games the three options come from a shared family definition. The material editions add real drawing treatments, but 17 card games sharing the same three looks does little to explain what makes a Bridge trick, Mahjong discard or Hanabi clue distinctive. The design registry also assigns most IDs by array order. Inserting a look ahead of another could silently repoint a saved design link. [Registry](../../src/game/designs.ts#L13-L18) · [Family definitions](../../src/game/visual-editions.json)
- The repo’s own actual-state census identifies **7 basic frame views, 19 partial views and 24 games without a typed live adapter**. These are different promises to an adopter. A consumer evaluating a game should be able to tell immediately if it accepts a real match, supports spectator replay, or provides synthetic artwork only. Source provenance and the 88 GitHub mappings already give the library a way to distinguish further research from a shipped capability. [Coverage](../game-coverage.json) · [GitHub sweep](../research/github-visual-sweep/README.md)
  - *Superseded note, 6 November 2026: after the Checkers fix the census lists 8 basic frame views, 18 partial views and 24 games without a typed live adapter. The review text above is unchanged.*
- A useful external benchmark is what a user can do with one board. Chessground demonstrates touch moves, premoves, annotation and editor use. Shudan demonstrates partial boards, stone markers and heat maps. Pachisi could distinguish itself by making a comparably coherent set of tasks work across multiple game families from one package. An authoritative host can continue to supply legality and private state. [Chessground](https://github.com/lichess-org/chessground#features) · [Shudan](https://github.com/SabakiHQ/Shudan#features)

## What the physics and visual tests prove

The local validator checked 672 recorded transitions. The mutation suite caught all 38 planted errors. Those are valuable constraints on trace integrity. Only 21 of 50 bundled traces reach a terminal frame. For example, the complete Car Racing demo consists of seven accelerations, and the Lunar Lander trace uses main thrust and idle. Neither trace exercises steering. Camera geometry, readable controls and useful feedback during a turn need their own fixtures. The existing Taxi terminal-state exception and Bridge rendering limitation remain documented. [Traces](../../src/game/game-demonstrations.json) · [Physics coverage](../physics.md)

I also removed the cell scene’s cue calculation **in a temporary copy**. The validator correctly reported the resulting missing cues as a Connect Four renderer error, then exited **0** in normal mode. This probe exercised the default validator in isolation. Other tests may catch a particular change. Baseline the known rendering limitation and fail on each new renderer finding, separately from accepted differences in game rules. [Validator exit condition](../../scripts/validate-demonstrations.py#L1957-L1965)

The browser’s 2,888 design/layout cases establish layout coverage. For non-Connect-Four designs the assertion checks the outer dimensions of the board, SVG and caption. The separate 722-frame probe checks finite geometry and renders each frame without a predecessor. Neither proves that a skin changes the pieces, a seat keeps its identity, or the last move settles in the right place. Keep these checks and add assertions on the actual pieces, positions, public labels and transitions. [Layout checks](../../scripts/browser-check.mjs#L117-L124) · [Frame probe](../../catalogue/main.tsx#L97-L105)

## Where I would invest next

1. Fix the three P1 reproductions. Add each failing example to local CI before changing the renderer. A designer should be able to trust that a different material, screen size or motion preference will preserve the same match state.
2. Make every advertised design earn its entry. Give it an explicit stable ID, supported input modes and at least one game-specific visual assertion. Keep shared material choices available as such. Count a distinct composition when its layout or interaction genuinely changes.
3. Prove depth on three contrasting games before applying the model to the other 47. **Pentago** should make the placed marble, rotating tray, direction and settled position legible. **Goofspiel** should keep the prize and both commitments visible while revealing the bids together. **Car Racing** should show steering, braking and lane movement against the track from authoritative frames. For each, run the same position through thumbnail, arena, replay and a packed consumer. Test one complete round or episode, a boundary case, touch/keyboard inspection and a reduced-motion still.
