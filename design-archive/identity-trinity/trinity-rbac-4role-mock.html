Trinity RBAC — the corrected 4-role model

The interactive prototype (eSlams Trinity.dc.html) still demos 5 roles (super_admin, manager). The shipped backend (packages/auth/src/permissions.ts) is 4 roles. This is the authoritative model to build to — matrix, who-manages-whom, and the corrected change-role dialog.

⚠ Build to this, not the prototype. Enforcement is server-side in workers/api via hasTrinityPermission() — nav-hiding is UX only, never the control.

The four roles

owner

Everything. The only role that sets roles, mints admin/owner, acts on an owner, and signs artifacts.

admin

Full read + write ops. Manages developer/researcher only. Cannot mint admins or sign artifacts.

developer

Runs + artifacts read/write; API keys (developer:execute). No user/role access.

researcher

Read-only: runs, artifacts, research. Default fail-closed role. No user/role access.

Who can manage whom

manageableRoles — the roles each actor may grant/revoke:

  • owner → can set owner admin developer researcher
  • admin → can set developer researcher (not admin/owner)
  • developer / researcher → cannot set roles

Hard rules (owner-gated)

  • 🔑Only owner sets roles & mints an admin or owner.
  • 🔑Only owner may act on another owner.
  • 🔑Only owner signs artifacts (canSignArtifacts).
  • 🔒Fail closed: unknown/missing role → researcher (least privilege). No "bare trinity → admin" escalation.
  • 👤No self-action in the users console — manage your own login under "Your account".
